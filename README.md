# 青柠商城管理系统（LimeMall）

一个完整的电商管理系统课程设计作品：**后台管理端 + 商城前台**，覆盖商品（SPU/SKU）、订单、会员、营销（优惠券）、系统权限（RBAC）与数据看板。

## 技术栈

| 层 | 技术 |
|----|------|
| 后端 | JDK 21 · Spring Boot 3.3 · MyBatis-Plus 3.5 · Spring Security + JWT · MySQL 5.7+ |
| 前端 | Vue 3 · Vite 5 · Element Plus · Pinia · Vue Router · ECharts |
| 接口文档 | SpringDoc OpenAPI（Swagger UI） |

## 功能清单

**后台管理端（`/admin/login`，独立入口）**

- 数据看板：今日订单/成交额、会员与商品统计、待办提醒（待发货/待退款）、30 天销售趋势、订单状态分布、分类销售占比、热销 TOP10、最新订单
- 商品管理：商品 SPU/SKU 两级维护、分类树、品牌管理、上下架、SKU 库存调整、图片上传（富文本入库前消毒）、评价管理（违规删除）
- 订单管理：多条件查询、订单详情（状态步骤条）、发货、关闭订单（自动回补库存/优惠券）、**未支付订单超时自动关闭**
- 退款审核：通过后自动关闭订单、回补库存销量、恢复优惠券
- 客服聊天（**会话制 + 一对一分派**）：会员咨询进入待接入队列，客服「接入」后会话绑定唯一接待人（CAS 抢占防重复接待）；**仅接待客服本人可回复**，超级管理员/运营**只读监管**（`ums:chat:reply` 仅客服专员角色持有，职责分离）；客服可结束会话，会员再发消息自动开启新咨询
- 会员管理：查询、启用/禁用（禁用后令牌即时失效）、等级与积分展示
- 营销管理：优惠券创建/编辑/上下线、领取与使用记录；**内容管理**（首页轮播图与公告后台可配）；**秒杀管理**（SKU 级秒杀价与时间窗口，下单时服务端强制生效）
- 系统管理：管理员 CRUD、角色管理与菜单/按钮级权限分配（RBAC）、**个人中心**（资料编辑：昵称/头像/邮箱/手机；修改密码）、**操作日志**（AOP 自动记录写操作，密码/私钥脱敏）

**商城前台（主站 `/`，自动进入 `/shop`）**

- 首页（分类导航、轮播海报与公告、限时秒杀楼层带倒计时、热销榜、新品）、**搜索联想**、商品搜索与分类浏览、商品详情（SKU 选择、评分与评价列表）
- 购物车（localStorage 持久化）、下单结算（收货信息 + 优惠券抵扣 + 满 99 包邮）
- 支付：**支持支付宝沙箱真实支付（配置即用）**，未配置时自动回退模拟支付；取消订单、确认收货、申请退款；**待付款订单显示支付倒计时，超时自动取消**
- 领券中心与我的优惠券、**积分商城**（100 积分 = 1 元兑换优惠券，兑换券由后台配置积分价；**积分明细**：获取/消费/过期流水与批次状态）
- **会员中心**：成长值/积分双账户、等级徽章（银/金/钻石）、升级进度、等级权益（金卡/钻石全场免运费、积分 1.2/1.5 倍）、**资料编辑**（昵称/性别/生日/手机改绑，手机唯一性校验）与**修改密码**
- **商品评价**：仅「已完成（确认收货）」订单可评价，一单一品一次（唯一键防刷），详情页评分汇总与评价列表，管理端可删除违规评价
- **在线客服**：右下角悬浮窗与客服实时对话
- 会员注册与登录（独立于后台的身份体系）

## 本地启动（Windows）

> 前置：MySQL 5.7+ 已启动（本机使用小皮面板）、JDK 21、Node 18+、Maven 3.9+

1. **导入数据库**（一次性）
   ```bash
   mysql -uroot -p < sql/init.sql
   ```
   默认连接 `127.0.0.1:3306`，账号 `root/123456`（可用环境变量 `MYSQL_USER` / `MYSQL_PASSWORD` 覆盖）。

2. **启动后端**（18080）
   ```bash
   start-backend.bat
   ```
   或手动：
   ```bash
   cd backend
   set JAVA_HOME=D:\program\Java\jdk-21
   mvn -s maven-settings.xml -DskipTests package
   "%JAVA_HOME%\bin\java" -jar target/limemall-backend.jar
   ```
   首次启动自动完成：管理员/会员密码 BCrypt 初始化、生成 60 条近 30 天演示订单（看板立即有数据）。

3. **启动前端**（5173）
   ```bash
   start-frontend.bat
   ```
   或手动：`cd frontend && npm install && npm run dev`

4. **访问**
   - 商城前台（主站）：http://localhost:5173/ （自动进入 `/shop`）
   - 后台管理（独立入口）：http://localhost:5173/admin/login
   - 接口文档：http://localhost:18080/swagger-ui.html
   - `localhost` 与 `127.0.0.1` 均可访问（Vite 已双栈监听）

> 端口说明：后端默认 **18080**（避开 Burp/Yakit 等安全工具默认占用的 8080），
> 可用环境变量 `SERVER_PORT` 覆盖；前端开发端口 5173。

## 支付宝沙箱接入（后台配置，即配即用）

系统内置**手工 RSA2 签名**的电脑网站支付（`alipay.trade.page.pay`），不依赖第三方 SDK。
配置入口在**管理端 → 系统管理 → 支付配置**（`sys_config` 表，保存立即生效，无需重启）：

1. 登录[支付宝开放平台](https://open.alipay.com/) → 控制台 → 沙箱应用，获取 **APPID**；
2. 在「开发信息 → 接口加签方式」选择 **自定义密钥（RSA2）**，生成密钥对并上传**应用公钥**，保存**应用私钥**与**支付宝公钥**；
3. 后台「支付配置」页填写：APPID、应用私钥、支付宝公钥、异步通知地址（公网可访问，如 `https://域名/api/portal/pay/alipay/notify`）、同步跳转地址，打开「启用支付」→ 保存；
4. 前台「去支付」跳转沙箱收银台（沙箱买家账号付款），异步通知经**验签 + 金额校验 + 幂等入账**后订单自动变为待发货。

> 安全设计：密钥在接口与审计日志中均为脱敏（`****` 预览，不回传明文）；配置优先级为 **后台配置 > 环境变量**；
> 环境变量 `ALIPAY_APP_ID / ALIPAY_PRIVATE_KEY / ALIPAY_PUBLIC_KEY / ALIPAY_NOTIFY_URL / ALIPAY_RETURN_URL`
> 作为自动化部署的兜底（两项都没有时前台支付回退模拟支付）。

### 本地开发：cloudflared 内网穿透（推荐）

异步通知需要公网 HTTPS 地址，用 Cloudflare 免费隧道即可（无需自有域名/备案）：

```bash
# 1) 安装 cloudflared 后，把本机后端映射为公网 HTTPS 地址（临时隧道，URL 每次启动变化）
cloudflared tunnel --url http://127.0.0.1:18080
# 输出形如：https://xxxx-yyyy.trycloudflare.com

# 2) 后台「支付配置」填写：
#    异步通知地址：https://xxxx-yyyy.trycloudflare.com/portal/pay/alipay/notify   ← 隧道直连后端，路径无 /api 前缀
#    同步跳转地址：http://localhost:5173/shop/orders                              ← 浏览器回跳本机即可
```

3. 沙箱付款后，支付宝服务器**实时回调**该 HTTPS 地址（验签 + 金额校验 + 幂等入账），订单立即变为待发货。

> 注意：trycloudflare 临时域名每次重启隧道都会变化，需同步更新后台的异步通知地址；
> 有自有域名时可创建 Named Tunnel 固定域名（`cloudflared tunnel create` + DNS 路由）。

## 安全设计

- **密码**：数据库一律 BCrypt 哈希存储（无明文/无 INIT 残留）；登录密码 **双通道 RSA 加密传输**——安全上下文用 WebCrypto（OAEP-SHA256），局域网 HTTP 等非安全上下文自动改用纯 JS RSA（PKCS#1 v1.5），**任何环境都不发送明文**；服务端**强制** `encrypted=true`，明文/降级请求直接拒绝（登录、注册、改密、新建管理员全链路一致）；接口调试用 `tools/password-encrypt.sh` 生成密文；生产必须启用 HTTPS（防主动 MITM 的权威防线）。
- **注入**：全部 SQL 走 MyBatis 参数化（`#{}`），无任何用户输入字符串拼接；动态 LIMIT 仅使用服务端常量/校验后整数。
- **越权**：RBAC 按钮级权限 + 数据归属校验（订单/优惠券/评价/聊天按会员隔离）；客服会话一对一分派；**前端路由级权限守卫**（直接输入 URL 访问无权页面会被拦截跳回看板），服务端 `@PreAuthorize` 兜底——双保险。
- **零硬编码凭据**：登录页不预填账号密码、无演示账号快捷填入/提示；演示口令仅记录于本文档，并建议公网部署前全部更换。
- **CORS 白名单**：默认放行本机与私有网段（开发/局域网演示），外网来源拒绝；**公网部署零维护**——Nginx 同源反代并剥离 Origin 头，白名单不会被触发（换任何域名/IP 均可）；仅当前后端分域部署（前端跨域直连后端）时，通过 `CORS_ALLOWED_ORIGINS` 配置一次即可。
- **登录防护**：连续失败 2 次后强制**图形验证码**（一次性、2 分钟有效），失败 5 次锁定 10 分钟；JWT 每次请求校验账号状态（禁用即失效）。
- **会员编号**：会员对外使用随机 10 位业务编号（`user_no`，不可遍历），后台会员管理与客服工作台可见；不再以自增 ID 对外沟通。
- **秒杀限购**：每人限购数量由活动配置（后台可调），下单时按时间窗口内有效购买量服务端强制校验。
- **审计**：后台写操作 AOP 留痕（密码/私钥正则脱敏）；SQL 控制台日志生产默认关闭。
- **实时客服通道**：原生 WebSocket（`/ws/chat`），**握手阶段**完成 JWT + 账号状态校验（非法令牌直接 403 拒绝升级）；服务端仅推送 `CHAT_UPDATE` 变更事件、数据仍走 REST（幂等易排障），断线 5 秒自动重连 + 15 秒轮询兜底。实测端到端推送延迟约 43ms。Nginx 需转发 Upgrade 头（部署文档已配置，cloudflared 天然支持 wss）。
- **健康检查**：`GET /health` 免登录返回应用与数据库状态，便于 cloudflared/反代链路排障与后续监控接入。
- **上传**：扩展名白名单 + UUID 重命名 + 仅管理员可用，排除 SVG。
- **支付**：异步通知 RSA2 验签 + app_id/金额校验 + 幂等入账。

## 设计要点

- **防超卖**：下单扣库存使用条件更新 `UPDATE ... SET stock = stock - ? WHERE id = ? AND stock >= ?`，影响行数为 0 即库存不足回滚，不依赖分布式锁。
- **订单状态机**：`0待付款 → 1待发货 → 2已发货 → 3已完成；0/1 → 4已关闭`，所有流转使用「条件更新（CAS）」实现，并发操作（重复支付/重复审核/双端同时关单）只有一方生效；关闭/退款时同事务回补库存、回退销量、恢复优惠券。
- **超时关单**：定时任务每分钟扫描超过支付时限（默认 30 分钟，`ORDER_PAY_TIMEOUT_MINUTES` 可配）的未支付订单自动关闭并回补库存，防止恶意锁单。
- **会员成长体系（双账户模型）**：**成长值**消费 1 元 = 1 点、只增不减、决定等级（普通/银卡 1000/金卡 5000/钻石 15000）——**花费积分永不掉级**；**积分**为站内货币，按等级倍率获取（1.0/1.0/1.2/1.5），在积分商城按 **100 积分 = 1 元** 兑换优惠券。获取与消耗比例恒定，防通胀。
- **积分商城**：复用优惠券体系，后台为每张券配置积分价（0=不参与兑换）；积分扣减与券库存均为条件更新，防超扣/超兑。
- **商品评价**：资格绑定「订单已完成 + 订单归属 + 一单一品一次（唯一键）」，评分聚合缓存于商品列表/详情；纯文本渲染防 XSS。
- **金额计算**：统一 `DECIMAL(10,2)`；`实付 = 商品总额 - 优惠 + 运费`，满 99 包邮；折扣券按订单金额比例计算并封顶。
- **RBAC**：菜单/按钮权限落库（`ums_menu.perm`），后端接口 `@PreAuthorize` 校验、前端按权限渲染，三级角色（超管/运营/客服）演示数据齐备。
- **双端认证隔离**：JWT 载荷 `type=ADMIN/MEMBER`，后台与前台令牌互不通用；登录连续失败 5 次锁定 10 分钟（内存限流）。
- **安全措施**：BCrypt 密码、参数化 SQL、越权校验（会员订单归属检查）、上传文件名服务端 UUID 生成、富文本入库前消毒（去 script/事件属性）、分页大小上限 100。
- **客服聊天**：消息纯文本存储与渲染（天然防 XSS）；实时性由 WebSocket 推送保障（握手鉴权）+ 15 秒轮询兜底（见「安全设计-实时客服通道」）。
